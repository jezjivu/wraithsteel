## Known risks
- Movement (dash/knockback/surge) uses client-side LinearVelocity on the player's own character;
  the server trusts positions (no speed sanity check yet) - add one before launch.
- Air detection for air slams uses the server's view of Humanoid.FloorMaterial/state, which can
  lag slightly behind the client.
- Map generation creates ~2,100 parts plus terrain; if performance suffers on phones, lower
  MapConfig counts (SakuraCount, bamboo per grove) or replace with a Studio build.
- Weapon swing directions (AnimationConfig weaponWindup/weaponStrike) are tuned by reasoning,
  not by eye; adjust signs if a swing looks backwards.
- RigBuilder relies on Players:CreateHumanoidModelFromDescription and Model:ScaleTo; if either
  fails at runtime the code falls back to block placeholders (warning in Output).
- Trades change two profiles that save separately. Both are saved immediately after a swap,
  but a server crash between the two saves could duplicate or lose a traded Spirit. Before
  launch, add a trade ledger (ProfileStore MessageAsync per side, idempotent by trade id).
- Procedural animation joint angles (AnimationConfig) are educated guesses for R15; tune in Studio.
- Weapon grip angle (`WeaponConfig.GripRotation`) and rack/viewport framing are computed, not
  eyeballed in Studio; expect small tweaks after the first look.
- Shop purchases do not check that the player is standing at the stall (server validates price,
  ownership and chapter only). Add a proximity check via `HubService.StationPosition` if needed.
- **Contracts are reconstructed**, not copied from the guide - expect renames when reconciling.
- **Nothing has run inside Roblox yet.** Code is type-checked with luau-lsp against Roblox
  definitions and pure logic is unit-tested, but engine behaviour (Humanoid movement of
  placeholder rigs, ProfileStore in Studio mock mode, remote timing) is unverified.
- Player dodge movement is client-driven; the server only grants i-frames. Add server-side
  position sanity checks before launch.
- Enemy/boss hit timing uses `task.delay(windup)`; once real animations exist, align windups
  with animation events.
- MarketService gift delivery to offline players relies on ProfileStore `MessageAsync`.
- `selene.toml` needs a Roblox std generated (`selene generate-roblox-std`), which could not be
  downloaded in the cloud sandbox; luau-lsp is used instead.
